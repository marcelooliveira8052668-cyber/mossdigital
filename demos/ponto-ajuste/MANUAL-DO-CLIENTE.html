1. O que você recebeu

Extraia o ZIP completo antes de começar. Não abra o site dentro do ZIP nem renomeie arquivos isolados.

A estrutura não depende de construtor pago nem de instalação de pacotes JavaScript. WhatsApp, publicação e Supabase precisam de internet. O modo sem banco não exige Supabase.

2. Abrir e testar no computador

  1. Faça uma cópia da pasta original para backup.
  2. Abra a pasta no Visual Studio Code.
  3. Para testar a vitrine, você pode abrir index.html no navegador. Para testar conexão com banco, prefira servidor local.
  4. Com Python instalado, abra o terminal na pasta e execute:
python -m http.server 8080 --bind 127.0.0.1

Depois abra http://127.0.0.1:8080/. Mantenha o terminal aberto. Para parar, use Ctrl + C. Alternativa: extensão Live Server no VS Code. Se o comando Python não existir, instale-o pelo site oficial ou use Live Server.

Importante: não distribua servidor de desenvolvimento com arquivos privados. Não coloque senhas, comprovantes, documentos ou backups de clientes dentro desta pasta.

3. Personalize antes de publicar

3.1 Nome, conteúdo e informações do negócio

Abra index.html. Procure “Ponto & Ajuste” e substitua pelo nome verdadeiro. Atualize título, descrição, marca, serviços, perguntas e rodapé. Confirme o que seu negócio realmente oferece. Não invente prazos, avaliações, depoimentos ou trabalhos.

As faixas de demonstração e o aviso junto ao formulário devem ser adaptados para as informações reais do negócio. Se continuar usando fotos de banco, mantenha a identificação de que são ilustrativas. O painel e o manual não precisam aparecer no menu público.

3.2 WhatsApp e mensagem

Abra config.js. Troque o número em whatsapp por país + DDD + número, só com dígitos. Exemplo de formato brasileiro: 55 + DDD + número. O número original é o atendimento MOSS, não um ateliê.

Abra também site.js e adapte o texto da variável texto no envio do formulário: retire a apresentação como demo MOSS e escreva a apresentação do seu ateliê. Em index.html, atualize os links de WhatsApp de reserva e do bloco sem JavaScript. A configuração nomeAtelie é apenas uma referência: ela não altera os textos HTML automaticamente.

O botão prepara a mensagem no navegador; o cliente precisa abrir o WhatsApp e tocar em Enviar. Não há leitura de conversas, anexo automático, cobrança ou confirmação de agenda.

3.3 Fotos e galeria

Troque os arquivos em img/ mantendo os nomes, ou altere os caminhos em index.html. Use fotos autorizadas do assunto correto. Se trocar o assunto de uma foto, atualize também alt, legenda e data-legenda. data-categoria deve continuar como “maquina” ou “manual” para os filtros existentes.

Prefira WebP, largura de 1.200 a 1.600 pixels e arquivos otimizados. Mantenha pelo menos seis fotos diferentes. Não use fotos de banco como “antes e depois” nem como prova de trabalhos realizados. As oito fotos originais têm origem registrada em img/fontes.json e em fontes-fotos.html.

3.4 Cores e ícone

As cores ficam no início de style.css, em :root. O ícone é icone.svg. Preserve contraste e legibilidade. Teste no celular depois de editar.

4. Publicação e teste no celular

Este é um site estático. Você pode usar uma hospedagem que aceite HTML, CSS, JavaScript e imagens, com HTTPS. Existem opções com planos gratuitos, sujeitos a limites e mudanças; domínio próprio pode ter custo. Combine responsabilidades e valores antes de contratar.

  1. Envie o conteúdo da pasta para a pasta pública da hospedagem. index.html deve ficar na raiz do endereço escolhido.
  2. Preserve a estrutura de pastas e letras dos nomes. Em servidores, “Foto.webp” e “foto.webp” podem ser arquivos diferentes.
  3. Ative HTTPS pelo provedor. Se usar domínio próprio, siga as instruções DNS do provedor — não há registro DNS universal para todas as hospedagens.
  4. Abra o endereço publicado em uma janela privada e no celular. “localhost” ou “127.0.0.1” no celular não acessam o computador; use o endereço publicado ou uma prévia privada disponibilizada pela MOSS.
  5. Teste menu, rolagem, serviços, filtros, ampliação, formulário, limpar e mensagem do WhatsApp. Confira o número e toque em Enviar apenas com uma mensagem de teste autorizada.
  6. Após adaptar o site real, remova noindex,nofollow de index.html se desejar indexação. Preserve noindex no painel. Isso não substitui controle de acesso.

Ao retirar o site do portal MOSS, ajuste os links relativos ../../index.html da faixa e rodapé, para seu endereço institucional ou créditos combinados.

5. Conectar o Supabase — opcional

O site funciona sem banco. Com Supabase, ele consulta serviços publicados, e o responsável autenticado registra pedidos manualmente. O formulário público não grava dados no banco. Isso evita expor uma caixa de entrada pública sem proteção contra spam.

A integração foi implementada e os fluxos foram testados com respostas simuladas. Nenhum projeto Supabase real foi criado ou conectado nesta entrega. Você deve executar o roteiro e os testes de permissão abaixo no seu projeto antes de usar dados reais.

5.1 Criar o projeto

  1. Entre no painel oficial em supabase.com/dashboard e crie um projeto dedicado. Consulte os limites e custos atuais; não ative serviços pagos sem entender a cobrança.
  2. Escolha uma senha forte para o banco e guarde em gerenciador seguro. Essa senha não vai no site.
  3. Espere o projeto ficar disponível. Em SQL Editor, abra uma nova consulta e cole todo o conteúdo de supabase/instalacao.sql.
  4. Execute a consulta. Confira as tabelas pa_servicos, pa_administradores e pa_pedidos, todas com RLS habilitada.

5.2 Criar o responsável

  1. Em Authentication → Users, crie manualmente um usuário com seu e-mail e uma senha forte. Confirme o e-mail conforme as opções do painel. Não há usuário ou senha padrão na entrega.
  2. Desative cadastros públicos em Authentication se o projeto for usado só para este painel.
  3. Copie o ID/UUID desse usuário. Volte ao SQL Editor e execute, substituindo o texto de exemplo:
insert into public.pa_administradores(id)
values ('COLE-AQUI-O-UUID-DO-USUARIO')
on conflict do nothing;

Essa operação é feita pelo proprietário no SQL Editor. O site não pode promover usuários a administradores. Quem tem conta no Auth mas não está nessa tabela não deve acessar pedidos.

5.3 Copiar apenas as informações públicas

Nas configurações/API do projeto, copie a URL, normalmente https://seu-projeto.supabase.co, e a chave publishable ou a chave legada anon. O nome exato dos menus pode variar.

window.PONTO_AJUSTE_CONFIG = Object.freeze({
  usarSupabase: true,
  supabaseUrl: 'https://SEU-PROJETO.supabase.co',
  supabaseChavePublica: 'SUA-CHAVE-PUBLICA',
  whatsapp: 'SEU-NUMERO-COM-PAIS-E-DDD',
  nomeAtelie: 'Seu ateliê'
});

Nunca use service_role, chave secret, senha de banco ou senha do responsável no JavaScript, HTML ou GitHub. A chave pública é visível por natureza; as políticas RLS fazem a proteção dos dados. O código rejeita chaves privadas conhecidas, mas você ainda precisa conferir o que colou.

5.4 Conferir a conexão pública

  1. Abra o site pelo servidor local ou HTTPS. Abaixo dos serviços, a mensagem deve indicar que o catálogo foi carregado do Supabase.
  2. Para verificar que é realmente o banco, altere temporariamente o texto de um serviço no Table Editor e recarregue o site. Depois restaure o texto.
  3. Mantenha os quatro códigos de serviço e os quatro registros ativos. O layout desta versão usa quatro serviços; remover um ou mudar o código aciona o catálogo local de reserva. Não prometa que o dado veio do banco se a mensagem indicar modo local.
  4. Se ocorrer falha, o site mostra o catálogo local e avisa. Isso não significa que pedidos foram gravados.

5.5 Entenda as tabelas

TabelaFinalidade e acesso
pa_servicosNome e descrição de quatro serviços. Visitantes leem somente ativos; só responsáveis autorizados podem alterar.
pa_administradoresIDs dos responsáveis. Usuário autenticado consulta apenas seu próprio vínculo; não pode criar vínculo pelo site.
pa_pedidosNome, contato, serviço, descrição, status e data. Somente responsáveis autorizados podem consultar, gravar, alterar e excluir.

Todos os responsáveis autorizados neste projeto compartilham os pedidos. Esta versão é para um ateliê; não é plataforma multiempresa. Não use o mesmo banco para negócios independentes sem redesenhar o isolamento.

6. Registrar e acompanhar pedidos

  1. Abra painel.html no endereço instalado, por exemplo https://seusite.com/painel.html.
  2. Entre com o e-mail e a senha criados no Supabase. O sistema verifica também seu vínculo de responsável.
  3. Receba a mensagem no seu WhatsApp e confirme o que pode registrar.
  4. Preencha nome, contato, serviço e descrição. Clique em Salvar pedido no banco. Só considere salvo após a confirmação da interface.
  5. A lista mostra os 100 pedidos mais recentes. Você pode filtrar os registros carregados por status, salvar status e atualizar a lista.
  6. Para pedidos anteriores aos 100 mais recentes, consulte o Table Editor com acesso de proprietário. Não há paginação ou busca histórica nesta versão.
  7. Excluir pedido pede confirmação e apaga definitivamente o registro principal. Backups do provedor seguem as condições dele.
  8. Clique em Sair ao terminar. Recarregar ou fechar a aba também perde a sessão local; o token não é guardado no armazenamento do navegador.

“Combinado” ou “Concluído” são anotações internas. Não são confirmação bancária, contrato eletrônico nem mensagem enviada ao cliente. Prazos, pagamentos e entrega continuam combinados manualmente.

7. Segurança e privacidade

  • Antes de usar dados reais: crie somente pedidos fictícios e teste com visitante sem login e usuário sem vínculo. Eles não podem ler ou gravar pedidos. Um retorno vazio em consulta sem permissão não dá direito de acesso.
  • Teste também tentativa de inserir vínculo de administrador usando a chave pública: o banco deve negar. Não desative RLS para “resolver” erros.
  • O proprietário no SQL Editor tem privilégios elevados. Uma consulta que funciona no SQL Editor não prova que o visitante tem as mesmas permissões.
  • Não exponha o acesso ao painel em computador compartilhado. Use HTTPS, senha forte, conta do projeto protegida e procedimentos de recuperação seguros.
  • Registre apenas dados necessários, com informação ao cliente e base legal adequada. Defina uma política de retenção, atendimento a correções/exclusões e acesso de colaboradores.
  • Se publicar para clientes reais, adapte a política de privacidade ao uso de WhatsApp, Supabase e hospedagem do seu negócio. Este manual não substitui orientação jurídica.
  • Faça backups seguros e teste a restauração. Limites, pausa por inatividade, logs, retenção e backup do Supabase dependem do plano vigente.
  • Não adicione integração de cartões, Pix automático ou coleta de documentos sem novo projeto de segurança e testes. Esta entrega não processa pagamentos.

Checklist antes de divulgar

  • Nome e serviços verdadeiros, fotos coerentes e autorizadas.
  • WhatsApp do negócio e mensagens sem apresentação fictícia da MOSS.
  • Texto legível e sem rolagem horizontal no celular.
  • Todos os botões testados e nenhum pagamento ou agendamento anunciado como automático.
  • Quando houver Supabase: login, CRUD de teste e RLS conferidos com e sem autorização.
  • Nenhuma senha ou chave privada nos arquivos publicados.
  • Hospedagem/HTTPS, responsabilidades, privacidade e backup definidos.
